# Windows 1.6.7 启动验收

代码和模拟测试不能替代新电脑验收。默认精简检查通过、再完成新电脑启动验收后发布；公开附件必须与验收 ZIP
的 SHA-256 一致。测试缺失 Runtime 时使用可还原的干净虚拟机，不从日常电脑卸载共享组件。

## 自动验证

`Build Windows release` 输入候选版本和完整提交 SHA，在对应分支触发：

- 固定 MSVC x64 / 静态 CRT，Rust 单测复用 release 编译依赖。
- PowerShell 5.1 语法与环境准备测试通过；检测、签名拒绝、失败恢复及并发互斥均有测试。
- 构建前后 PE 普通/延迟导入表通过，不能依赖外部 WebView2Loader 或 VC++ DLL。
- 最终 ZIP 在独立目录、精简 PATH 下能打开实际控制台窗口。
- 从同一 ZIP 执行一次安装和升级，确认启动、数据保留及卸载快捷方式。

默认不重复运行日常 CI 的全量测试。勾选工作流的 `full_validation` 后才额外运行
插件/服务端全量测试、OCR、端口冲突、失败回滚与安装目录迁移检查。

本地可运行 `python scripts/test_windows_pe.py`。旧版回归检查使用官方 v1.6.6 ZIP：
SHA-256 `0b2d1f1f55d0dabd4998c16ac6303ac427a7bed4f4ec6f778acfc500d9e6d0b7`。
解压后运行 `python scripts/windows_pe.py <旧版EXE>`，应拒绝 `webview2loader.dll`。

## 干净 Windows 10 / 11 x64（普通用户）

记录系统版本、是否预装 Runtime、候选提交、ZIP 哈希、结果和诊断日志。

| 场景 | 预期结果 |
| --- | --- |
| 已安装 Runtime，没有开发工具或额外 VC++ 运行库 | 解压、双击即打开控制台，无 DLL 错误 |
| 未安装 Runtime，联网 | 显示原生准备窗口，自动下载和安装，完成后继续打开控制台 |
| 准备过程中重复双击 | 只有一次安装和一个准备窗口 |
| 未安装 Runtime，断网 | 出现可操作错误和日志入口；恢复网络后“重试”可以继续 |
| 安装被企业策略阻止 | 显示错误，提供官方安装入口，无无限重试 |
| 未安装 Runtime，使用 `--autostart` | 记录诊断后退出，不弹安装窗口；主动双击可准备 |
| 首次准备已写日志 | 点击安装可继续，已有启动日志不会被当成无关文件阻止安装 |
| 从旧版安装升级 | 新控制台正常启动，配置、任务记录和自启选择保留 |

在用户已复现问题的新电脑上执行同样的“完整解压、双击”流程。控制台打开后再完成服务安装、
健康检查，并使用测试配置翻译一份小 PDF，确认输出能够打开。已有安装升级后检查原记录。

## 交付

版本使用 1.6.7，不替换 1.6.6 附件。只发布已通过验证的 ZIP，生成同一字节内容的
`windows-update.json` 和校验信息，发布后重新下载核对。旧版不能启动的用户通过下载
新版 ZIP、运行新 EXE 完成恢复，无需预先卸载或手工复制 DLL。
