# README 维护规范

[返回项目首页](../README.md) · [开发维护笔记](development-notes.md)

修改首页或新增文档时，先按本规范确定内容归属，再编辑和检查。人工与 AI 编辑均适用。

## 内容放在哪里

| 内容 | 维护位置 |
| --- | --- |
| 项目定位、核心能力、真实预览、快速开始、文档入口 | 根目录 README |
| 安装图文、API 配置、完整操作、参数、更新卸载、故障排查 | [使用指南](user-guide.md) |
| 开发环境、源码部署、测试与发布 | [开发维护笔记](development-notes.md) |
| 服务端接口与兼容性 | [服务端说明](../server/README.md) |
| 单项机制、验收细节和数据来源 | `docs/` 下对应专题文档 |
| 各版本变化 | [CHANGELOG](../CHANGELOG.md) |
| 未实现的功能方向 | 首页 TODO |
| 官网布局、导航、教程章节路由与样式 | `website/`；正文仍维护在本表对应的 Markdown 文档 |

新功能先更新对应指南和更新记录。只有影响核心能力或首次使用路径时才补充首页，不在首页末尾追加专题教程、调试记录或版本公告。
已有专题文档优先更新；首页只给出简短说明和准确入口，避免多处维护同一套细节。

官网使用 `website/routes.json` 将使用指南的显式锚点映射为独立教程页。新增章节时同时更新路由；
不在 HTML 模板中复制教程正文。官网更新记录直接读取 CHANGELOG，版本读取插件元数据。
修改官网后按[开发维护笔记](development-notes.md#官网开发与发布)执行构建与验证。

## 首页结构与篇幅

顺序保持为：项目介绍与徽章 → 核心功能与预览 → 快速开始 → 文档导航与常见问题 → TODO → 反馈与贡献、来源、许可证。

- 快速开始必须覆盖本地服务、XPI、API 测试和首次翻译，Windows/macOS 用户都能走通。
- 目标为 180–250 行；超过 280 行时检查是否应迁移详细内容。检查器仅提示，不因篇幅单独失败。
- 使用短段落和必要列表；避免重复导航、宽表格、过多徽章、冗余提示和解释性小字。
- 优先使用真实界面截图，提供描述操作或结果的替代文本；过时或容易误解的截图应更换。
- 图注只说明操作或结果，不写“实机截图”、截图版本、服务商免责等重复说明。
- 教程说明当前操作，功能起始版本和版本沿革归入 CHANGELOG；必要的升级排错集中到维护章节。
- 保留有效参数、限制和排错信息；开发验收命令放开发文档，HTTP 接口放服务端文档。
- 优先展示全文翻译与划词精读，截图与操作步骤相邻，避免重复讲解图中已清楚展示的内容。
- TODO 只保留标题和未勾选清单，不附加发布时间、优先级或免责声明。功能完成后移出 TODO，更新功能介绍、指南和 CHANGELOG。

## 事实与兼容性

- 菜单、默认参数、支持版本和安装命令必须与当前实现一致。建议参数要写明是建议，不冒充默认值。
- 不将计划中的功能写入已支持列表，不添加没有证据的效果或性能承诺。
- 明确区分本地 PDF 处理与云端 API 请求、本地服务地址与 API 地址。
- 保留首页版本标记 `<!-- release-version -->`，后接一个空格及反引号包裹的版本号。首页只能出现一次该标记；发布脚本依赖此格式。
- 版本须与 `plugin/package.json`、`server/pyproject.toml` 和 `server/server.py` 一致。文档整理不单独改版本。
- 保留原有显式锚点：`features`、`quick-start`、`windows`、`macos`、`installation`、`api-configuration`、`usage`、`translation-options`、`task-management`、`maintenance`、`troubleshooting`、`advanced`、`community`。
- 移动章节后，旧锚点保留在相应摘要或导航处，并链接到新章节；不靠删除检查器中的保护项解决失败。
- 修改标题时检查隐式标题锚点的引用。跨文档的长期入口优先使用显式锚点。
- 图片和文件使用相对路径；迁入 `docs/` 后重新核对路径，不写个人绝对路径。
- 保留上游来源、许可证及第三方归属；保留工作区中已有的有效文档改动。

## 自动检查

在仓库根目录使用 Python 3.12 或更新版本运行：

```bash
python3 scripts/check_docs.py
python3 -m unittest discover -s scripts -p 'test_check_docs.py'
git diff --check
```

检查器只读扫描首页、使用指南、本规范、开发维护笔记及 AI 编辑指引；本地链接目标中的 Markdown 章节也会被解析。
支持行内链接与图片、引用式链接、HTML `href` / `src` / `id` / 命名锚点，以及 ATX 标题（`#` 到 `######`）。
围栏代码块、行内代码和 HTML 注释中的示例不按链接检查。复杂 HTML 排版和其他 Markdown 扩展仍需人工预览。

本地文件缺失、无效章节、重复显式锚点、旧入口丢失或版本标记损坏会导致非零退出，并报告文件与行号。
文档 CI 独立运行，覆盖文档、素材、版本来源及检查设施变更；不改变业务 CI 的触发规则。
外网链接不发起自动请求，避免网络波动导致误报。新增或修改的下载、反馈和外部文档入口由编辑者人工打开核对。

## 提交前检查

- [ ] 新内容已放到正确文档，首页保持简洁。
- [ ] Windows/macOS 的首次使用路径完整，命令与实现一致。
- [ ] 已预览首页与指南，图片、表格、折叠内容显示正常。
- [ ] 文件链接、章节入口和旧锚点有效，外部入口已人工核对。
- [ ] 版本标记与声明版本一致，TODO 与实际功能状态一致。
- [ ] 自动检查通过，已有文档内容、来源和许可证未丢失。
