# Codex 安装、验收与回退

[返回使用指南](user-guide.md#api-configuration) · [模型与套餐比较](codex-model-value-2026-10-03.md) · [开发环境](development-notes.md#macos-独立开发环境)

Codex 接入自 v1.8.1 起提供。构建和自动化检查由发布流程负责；下文真实调用、论文质量和 macOS／Windows 实际使用仍需用户核对，没有速度或吞吐量门槛。文末保留此前开发版本的检查记录。

## 使用本版

按 [使用指南](user-guide.md#installation) 分别将 Zotero 插件与本地服务升级至 v1.8.1 或更新版本。正式发布提供 XPI、PyPI 服务端包和 Windows 控制中心 ZIP；源码以匹配的公开 tag 为准。

需要隔离验收时，可从对应版本源码根目录使用开发入口。先退出正式 Zotero，再按平台执行：

| 平台 | 初始化 | 启动 | 停止 |
| --- | --- | --- | --- |
| macOS | `./scripts/dev.sh init` | `./scripts/dev.sh start` | `./scripts/dev.sh stop` |
| Windows PowerShell | `.\scripts\dev.ps1 init` | `.\scripts\dev.ps1 start` | `.\scripts\dev.ps1 stop` |

具体依赖和启动参数见下方开发环境链接。隔离环境保留独立的配置和任务数据；实际模型请求及译文质量按本文流程验证。

## 安装和配置

1. 按 [Codex CLI 官方安装指南](https://learn.chatgpt.com/docs/codex/cli) 选择 macOS 或 Windows 安装方式。在运行本地翻译服务的同一操作系统用户下完成 ChatGPT 登录。Windows 本版使用原生 CLI，与本地服务保持同一系统环境。
2. 在终端运行 `codex --version`，确认 **0.153.4 或更新的兼容版本**，再运行 `codex login status`。尚未登录时执行 `codex login`，按提示选择 ChatGPT 登录。模型权限取决于该账号的套餐；桌面应用可用不代表 CLI 一定可用。
3. 启动配套本地服务，打开 Zotero → 设置 → PDF2zh Pro → 管理配置 → ＋新增，在“本地与账号”中选择 **Codex**。
4. CLI 路径先留空自动发现；找不到时填写实际可执行文件的完整路径。macOS 可用 `command -v codex` 查找，Windows PowerShell 可用 `(Get-Command codex).Source` 查找；npm 启动器由服务定位其原生 `codex.exe`，定位失败时指定原生程序路径。字段只填路径，不填启动参数。
5. 点击 **获取模型**，选择 `gpt-6-luna`，推理档位保持模型默认值。模型目录反映可发现的条目，权限仍需实际请求确认。速度固定为 Standard。
6. 用户主动点击 **测试**，确认一次短翻译成功，再点 **保存并使用**。此步骤会消耗账号额度；获取模型、版本和登录检查不用于证明译文质量。

Codex 配置不填写 API Key 或 API URL。登录由 CLI 管理，插件不复制登录令牌。翻译仍向模型服务发送待翻译文本及所需上下文；PDF 解析、排版和附件导入在本地完成。

划词功能可选择独立 Codex 配置，也可跟随全文配置。保留现有 CommandGo 配置，便于对照和切换；失败时不会自动改用另一付费服务。

### 无需 TUN 的代理设置

编辑 Codex 配置，在 **Codex 代理** 中选择：

| 模式 | 使用方式 |
| --- | --- |
| 跟随服务环境（默认） | 继承 Python 服务启动时的代理环境变量。终端后来设置代理，不会改变已经运行的服务。 |
| 指定代理 | 填写 `http://127.0.0.1:7897` 等 HTTP(S) 地址。端口须与代理软件的 HTTP／Mixed 监听端口一致；保持代理软件运行即可关闭 TUN 复验。 |
| 直接连接 | 清除 Codex 子进程的代理地址变量并设置全量绕过；需要可直接访问 Codex，系统 TUN 路由仍可能生效。 |

地址指向**本地服务所在电脑**，不是远程 Zotero 所在电脑；不要填写 API URL、SOCKS 专用端口、账号密码、路径或查询参数。设置随配置保存，模型发现、连接测试、全文、术语提取和划词都使用它。只有“指定代理”保存代理地址。

代理配置只修改该 Codex 子进程的环境，不修改系统代理、Python 服务环境或其他模型配置。不同代理设置使用独立连接；已有请求保留原代理，新请求使用当前配置。代理地址不改变译文缓存标识，验证网络时使用“测试”，不要只观察缓存命中。

插件和服务需分别升级至 v1.8.1 或更新版本，服务应支持 `codexProxy` 能力。旧服务会明确提示升级，不会静默忽略指定代理。

复验步骤：关闭 TUN、保持代理软件运行 → 填写正确 HTTP／Mixed 地址 → 获取模型 → 测试 → 保存并使用 → 全文固定页与划词各验证一次。再改成无监听端口，应失败且不会自动回到直连；恢复地址后应可重新测试。macOS／Windows 均按此流程验证。

### 当前协议验证与边界

开发时以 CLI 0.153.4 完成了不含模型推理的协议检查：复用 ChatGPT 登录、禁用已配置 MCP 及 hooks／插件／应用／工具、限定临时目录只读权限，并确认指令来源为空。
运行时直接创建独立的临时会话（`thread/start` 的 `ephemeral: true`），结束后取消订阅。该版本已支持直接临时会话，所以无需原计划中的空种子会话和分支，也不会留下持久化种子。

这次协议检查中的模型目录未返回 `gpt-6-luna`，返回了 Astra 与 5.6 系列条目。目录受 CLI、账号和开放进度影响，不能据此断言所有账号都缺少 Luna，也不能将已有 ChatGPT 登录当作 Luna 可调用证明。若所选模型不可用，配置测试会报错，由用户选择可用模型；不会自动替换默认模型。

后续排查已确认本机旧 CLI 是目录缺少 Luna 的因素：官方 0.156.1 加入 Luna，0.159.1 加入 Sol 6.1。本机已更新到 0.160.0，用户反馈开启 TUN 后连接测试可用；关闭 TUN 后的指定代理方式仍需本轮复验。[官方更新日志](https://learn.chatgpt.com/docs/changelog)

真实翻译请求、译文质量及 Windows 原生使用尚待用户验收。协议检查成功不代表这些项目已通过。

## 验收准备

使用 [macOS 隔离开发入口](development-notes.md#macos-独立开发环境) 或 [Windows 隔离开发入口](development-notes.md#windows-独立开发环境)。开发服务监听 `127.0.0.1:8891`，使用独立 Profile、文献库、配置和任务数据。先正常退出正式 Zotero，再启动开发实例。

运行对应平台的 `prepare-samples` 准备并校验固定论文。先验收 Attention `1706.03762v7` 第 3 页、BERT `1810.04805v2` 第 3 页、ResNet `1512.03385v1` 第 4 页；是否扩展至整篇由用户决定。样本准备不发起模型调用。

记录操作系统、Zotero 版本、插件／服务版本、构建提交、Codex CLI 版本、模型及推理档位。套餐与用量面板记录可用于个人费用比较；反馈时去除账号标识和敏感信息。

### 固定划词小样

以下为自编控制样例，可放进测试 PDF 或本地接口请求；用于检查功能，不代替真实论文质量验收。

| 模式 | 选文／上下文 | 核对重点 |
| --- | --- | --- |
| 句段翻译 | `The model uses attention to compare tokens in a sequence.` | 完整表达模型用注意力比较序列中的词元；无额外分析或漏译 |
| 个人释义 | 选词 `attention` | 返回可保存的结构化词条；重复打开能够复用 |
| 上下文解释 | 选词 `attention`；上下文为上面的完整句子 | 解释机器学习中的注意力含义，避免只解释日常“注意” |
| 公式与引用 | `We minimize L = -log p(y|x), as shown in Eq. (2) [3].` | 保留公式、编号及引用，翻译剩余正文 |

## 用户验收清单

| 场景 | 操作 | 预期结果 |
| --- | --- | --- |
| 模型配置 | 新建、保存、重新打开 Codex 配置 | 模型和推理选择保留，API Key／URL 不参与配置 |
| 安装与登录 | 获取模型，再主动测试连接 | 已登录账号可调用所选模型；不存在重复测试请求 |
| PDF 输出 | 翻译固定页，生成双语 PDF | 正文可读，公式、引用、术语和对应关系正确，结果附件可导入 |
| 精确选句 | 选择一个完整英文句子 | 结果只对应选句，复制不夹带整段参考 |
| 个人释义 | 对一个缺词生成释义，再重复打开 | 结构完整，可保存并复用；已有离线词条可继续使用 |
| 上下文解释 | 点击结合上下文解释 | 解释对应当前论文语境；上下文不足时给出提示 |
| 独立配置 | 全文用现有服务，划词选 Codex，再改为跟随全文 | 仅后续新请求使用对应配置；旧结果不覆盖新结果 |
| 缓存 | 重复相同选文；切换模型或推理档位再请求 | 相同配置可复用；影响译文的配置改变后重新生成 |
| 取消 | 生成中取消任务或关闭选文，再发起其他内容 | 任务停止，旧请求不会重新弹出或覆盖新结果 |
| 恢复与补译 | 对有未完成段落的任务补译 | 已验证结果保留，只补充仍需处理的内容 |
| 异常配置 | 临时填一个不存在的 CLI 路径或不可用模型 | 错误明确；恢复配置后可重新测试，不切换到其他服务 |
| 账号异常 | 遇到登录失效或额度不足时检查提示 | 能识别原因；不将失败写入成功缓存 |
| 进程退出 | 正常结束开发服务，检查相关子进程 | 本集成创建的 app-server 被回收，用户其他 Codex 会话不受影响 |
| 双平台 | macOS、Windows 分别重复配置和小样本流程 | 路径、启动、生成和关闭均正确，包括含空格的 CLI 路径 |

登录失效、额度不足和进程崩溃由自动化模拟覆盖；不需要为了验收主动耗尽额度或影响其他会话。真实故障发生时保留脱敏诊断即可。

质量对照使用相同内容，标出漏译、错译、术语、公式引用和多余说明。先比较 Codex Luna 与现有 CommandGo Luna；仅在有具体质量问题时由用户选择更强模型复验。已缓存内容不会产生同等的新模型消耗，比较时应记录是否使用重翻。用量未提供时标为未知，不按零计算。

## 故障排查

| 提示或现象 | 处理 |
| --- | --- |
| 本地服务连接失败 | 先检查开发服务与 8891 地址；Codex 登录无法修复服务未启动 |
| 找不到 Codex | 检查 CLI 安装与完整路径；桌面服务的 PATH 可能不同于终端 |
| 终端已登录，插件提示未登录 | 确认启动服务的系统用户与登录用户相同；不要用管理员或系统服务身份替代个人用户 |
| CLI 版本或协议不兼容 | 按官方指南更新 CLI，重启本地服务；记录版本和错误码 |
| 模型可列出但调用失败 | 核对套餐、组织权限和所选模型；模型目录不是授权证明 |
| 额度不足 | 在 CLI `/status` 或账号用量面板查看重置时间；等待恢复或手动选择已保存配置 |
| 生成超时或中断 | 检查网络及服务诊断；确认前次请求已结束后再手动重试 |
| 用量显示未知 | 上游缺少相应统计，不能据此认定没有消耗 |
| 旧版服务拒绝 Codex 配置 | 同时更新插件和配套服务；用 `/health` 中的 Codex 能力判断，不能只比较版本号 |

从任务卡片或设置页导出诊断 ZIP，附复现步骤、时间、任务 ID 与版本信息。先按 [诊断说明](user-guide.md#diagnostics) 检查脱敏；不上传登录凭据、完整用户配置或私人论文正文。

## 回退

1. 先完成或取消正在进行的任务；在插件里手动选择原有 CommandGo 或其他已保存配置，新任务即可走原路线。
2. 使用隔离开发环境时，运行对应平台的 `stop`，再正常打开正式 Zotero。开发数据保留，不覆盖正式文献库。
3. 若曾手动替换正式安装，先备份插件配置和服务实际数据目录，再同时恢复原插件与原服务版本。升级基线为 v1.8.0；不要只回退其中一个组件。
4. 保留 Codex 配置便于之后继续验收；旧版服务不能使用它。不要删除原任务、词典、翻译记忆或 Codex 登录目录来“修复”回退。

公开安装包的升级说明以对应版本发布记录为准；下方历史开发检查记录不代表真实模型调用或双平台实际使用已经通过。
