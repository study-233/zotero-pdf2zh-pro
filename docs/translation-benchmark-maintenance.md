### 候选问题与处理边界

[候选清单](../benchmarks/translation/maintenance/2026-10-15-v1/candidates.json) 是可离线校验的证据索引，
不是自动可调用的新样本集。每条包含关联组、预期检查、原结果哈希及错误证据位置。

- 翻译：引用括号吞入正文、普通英文残留、跨栏重复、Transfer 名称、语域限定、可能性与变量关系、
  选段越界、ghost 限定遗漏、预热计数范围、服务时机误译复现。
- 排版/覆盖：根号横线错位、表格竖排标签未译，与模型语义分开检查。
- 标注：DuckDB 的 URL 保留规则误含尾随标点。当前评审保留原规则并记录豁免，下一数据版本修订。
- 流程：TLS 失败后的部分 PDF、未执行页面、未知用量和显式重测，单列于质量集之外。

`notoriously` 残留也出现在先前 2 路连接实验中；不能只凭并发实验中的分布，认定由 4 路造成。
同页重复、热缓存输出和术语变体归入同一关联证据组，不重复累计为独立发现。
本轮只登记问题，没有修改翻译逻辑、提示词、并发参数或冻结数据。

## 可复用的维护命令

只需公开元数据即可运行的校验，已加入现有 `offline` 测试发现流程，普通 CI 无需 PDF、凭据或模型：

```bash
python -m benchmarks.translation maintenance verify \
  --records benchmarks/translation/maintenance/2026-10-15-v1
```

私有证据包按仓库相对路径保存。搬到另一个目录后，用新的根目录定位，不需要修改个人绝对路径：

```bash
python -m benchmarks.translation maintenance verify \
  --records benchmarks/translation/maintenance/2026-10-15-v1 \
  --evidence-root .
python -m benchmarks.translation maintenance report \
  --records benchmarks/translation/maintenance/2026-10-15-v1 \
  --evidence-root . --output .local-dev/translation-bench/reports/maintenance-20261015-v1
```

报告输出离线 HTML、JSON、CSV，包含运行状态、评分和复核覆盖、严重问题率、无产物/未执行项、
PDF 内容与排版；详细页保留原文、译文、评分证据、耗时和 Token。模型配置和实验范围分别列示，
不生成跨版本总排名。输出目录已存在时拒绝覆盖。

公开记录不包含受限全文、PDF 或登录凭据；`--evidence-root` 校验需自行保存私有运行目录及渲染
检查文件。元数据校验成功会标明 `evidence_verified: false`，不能冒充本机产物核验。
完整校验核对文件哈希、结果与评分绑定、加权分、全部应复核项目、暴露来源和候选证据。

## 下次收尾流程

1. 登记本次范围内的运行目录、原始文件哈希及缺项。读取历史结果，默认不调用模型。
2. 通过现有 `review prepare` / `pdf-prepare` 评阅；扣分附原文与译文证据，保留未评审状态。
3. 判断变化先 `review new-round` 归档，说明校准原因，不编辑旧轮记录或冻结规则。
4. 使用 `review audit` 取得当前评分哈希及抽样项；完成第二遍核对后导入。评分变动后重新复核。
5. 另建版本目录，复制维护记录格式，更新 inventory、exposure、candidates、calibration 和文件哈希。
   新版本可引用旧记录的相同证据，旧目录不覆盖。候选去重、关联分组后才编制后续真实调用配方。
6. 运行元数据和私有证据校验，再向新目录生成报告。检查原始结果、数据版本和晋升登记未变。
7. `baseline promote` 始终是另一个明确操作；补评分、报告生成或发现更高分均不触发晋升。
