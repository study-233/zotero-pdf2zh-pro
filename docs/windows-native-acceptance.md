# Windows 原生候选版验收记录

[开发维护笔记](development-notes.md) · [使用指南](user-guide.md)

本页记录第一轮未公开发布的 1.8.2 原生候选构建；最新安装流程见
[单 EXE 安装验收](windows-installer-acceptance.md)。Windows 控制中心已改为 Rust + Win32；
翻译服务仍为 Python，插件与公共服务端的版本号保持一致。候选包不能与公开 PyPI
同版包混用：安装时需要候选服务 wheel，安装器会校验其 SHA-256。

## 已实现

- 标准 Cargo 工程、Windows SDK 资源编译、静态 CRT、图标、版本信息、DPI 清单；
  控制中心移除 Tauri、网页资源及 WebView2 检测、下载和安装流程。
- 380 × 280 逻辑像素面板、原生设置、目录选择、托盘、自启、单实例与 Explorer
  重启通知恢复；关闭面板销毁窗口，首次安装和更新后的实例交接仅进入托盘。
- 启动延迟 60 秒和每 24 小时稳定版检查；网络失败按 15 分钟、1 小时、6 小时重试，
  安装失败版本暂停自动重试，手动检查及修复可重试。
- 锁文件导出带哈希的依赖清单，Python 固定为 3.13.15；候选环境与共享 uv 缓存
  使用硬链接，下载包校验后保留，安装器检查依赖 RECORD 并修复缺失或损坏的包。
- 原子维护接单门、连续空闲 60 秒、候选健康与目录验证、持久化事务、本地回退与
  中断恢复；后台划词请求超时后仍在运行时，也会阻止切换。
- 5 MiB 日志轮转及三份历史文件、硬链接去重空间报告、七天旧版及失效候选清理、
  uv cache prune；用户数据、词库及独立模型字体缓存不自动清理。
- 插件只重试带明确未接收标记的维护响应；切换期间先以健康请求等待端口恢复。
  原请求已经接收或结果不确定时不会自动再次提交。

普通更新仍下载完整控制 ZIP 和服务 wheel，服务 wheel 内置的 OCR 资源随包下载。
本轮没有二进制差分，也没有改变 PDF 引擎的首次加载策略；健康后的低优先级预检
只检查已有缓存文件，不下载模型或字体。

## 资源及下载量

统一关闭面板后连续三次采样，窗口出现时间为 223–290 毫秒，中位数 225 毫秒；
工作集约 67.0–68.0 MiB，私有内存约 35.4–37.3 MiB。五秒 CPU 增量分别为
0、15.625、0 毫秒，均无子进程。此前单次样本较低，不作为最终代表值。
这些数字只统计控制中心，测试时没有启动翻译服务，不代表 Python 后端的内存占用。
详细条件和每次数字以交付包中的 resource-report.json 为准。

| 项目 | 旧控制中心 | 原生候选 |
| --- | --- | --- |
| EXE 大小 | 13.86 MiB | 5.57 MiB，减少约 60% |
| 控制 ZIP | 未保留相同口径旧 ZIP | 约 2.55 MiB |
| 服务 wheel | 内置资源仍随服务包发布 | 约 20.10 MiB |
| 实际内存、CPU与启动时间 | 未启动日常安装作对比 | 见 resource-report.json；不作跨机器推断 |
| 首份 PDF 准备耗时 | 未取得可比基线 | 保留原加载策略，完整基准待补 |

离线复用测试使用 `UV_OFFLINE=1`，连续三次准备新环境并切换同版候选，记录网络
下载量与硬链接去重后的空间变化。其结果见 `reuse-report.json`。它验证缓存完整时
的复用，不等同于连续三次真实发布升级，也不代表首次安装下载量为零。

三次切换的网络下载量均为 0，累计新增去重文件内容为 166,563,673 字节（约
158.85 MiB）；每次约 53 MiB。三次环境准备分别约 57.7、63.0、57.5 秒，包含
依赖逐文件校验；连同健康验证与切换分别约 83.9、89.9、87.0 秒。原服务在环境
准备期间仍可运行。逻辑文件总量约 3.21 GiB，按硬链接去重约 0.93 GiB；这些
数字统计文件内容长度，不等同于 NTFS 簇分配量。旧环境及本地备份仍有空间成本。

## 测试隔离修正记录

验收中发现原有测试覆盖只隔离了自启 Run 路径，StartupApproved 路径仍指向当前
用户的系统键。此前生命周期测试曾尝试删除本产品的同名批准项；没有运行前快照，
无法判断它原来是否存在。现已将两个路径一起隔离并增加测试断言；若日常安装曾
在任务管理器中禁用自启，需要按原选择恢复该标记。用户已确认原状态为已启用，
因此没有补写禁用标记。正式 Run 自启命令未被测试改写。

现存历史 formal-before.json 来自 10 月 2 日，正式服务文件曾于 10 月 9 日更新，
因此旧快照不是本轮哈希基线。本轮没有对正式安装执行安装、更新、启停或数据清理。

完整回归期间，测试脚本曾在 GUI 启动确认结束前停止服务，产生一次进程归属确认
错误；用户截图指向的也是该隔离实例。现已在健康判断后等待启动子进程结束，
并修正默认卸载后等待异步清理结束的时序。控制中心也会显示脚本的实际错误原因。

## 复现入口

使用专用临时目录，先构建服务 wheel、原生 EXE，再生成 Windows ZIP。详见
[Windows 原生构建](development-notes.md)。`scripts/test_windows_native_install.ps1`
验证首次按钮安装；`scripts/test_windows_update_reuse.ps1` 验证三次离线切换；
`scripts/test_windows_lifecycle.ps1` 验证安装、更新、卸载、重装及迁移。

这些脚本的目录、注册表和端口必须与日常安装隔离。不要把测试 Root 指向日常安装。
