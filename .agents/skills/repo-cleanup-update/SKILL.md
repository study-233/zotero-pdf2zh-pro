# 项目清理与更新

先确认仓库根目录、当前分支、上游和已有改动。读项目维护约定，查明文档源文件、生成物和正式发布渠道。用户要求同步远端时，先检查分支是否分叉，保护未提交改动。

## 盘点与计划

结合 Git 跟踪状态、文件引用、构建与发布入口、历史用途，判断候选项。查不到静态引用时，继续核对约定路径、动态加载和外部下载链接。疑似重复文件先比对内容，再确定保留副本。

报告逐项列出「路径｜证据｜建议动作｜影响或恢复方式」。区分保留、更新、归档、删除和待核实项。用户要求先看报告或批准计划时，交付到该阶段并等候；已批准的计划直接执行。

## 执行顺序

1. **校准 README 和官网。** 以最新正式 Release 及可下载制品核对功能、安装步骤和平台范围。下一版内容放入「未发布」或文档预览。用截图或简图展示操作位置和完成状态，保留可复制的命令、地址和必要限制，给图写替代文本。删去重复提示和装饰性小字。
2. **精简维护文档和 Skill。** 每个主题确定一处正文，其他入口链接过去。编辑源文件后重新生成派生文档。Skill 保留触发条件、关键步骤和验收标准，低频细节放入引用文档。更新旧路径，保留公共锚点、署名和许可证。
3. **整理旧文件。** 旧方案、验收证据和恢复备份按项目约定归档，记录原路径和新路径，核对归档可读。本地日志、备份和个人资料留在本地归档。保留用户数据、在用运行环境及已有改动。仅删除已确认无用且在授权范围内的内容；项目提供清理预览时先核对清单。
4. **验证版本与入口。** 运行受影响的文档、Skill 和工作区检查。有官网改动时构建生产预览，检查桌面与手机上的图片、旧链接、搜索和下载。确认首页、教程和更新记录指向同一正式版。新版本制品可下载后，再同步该版 README 和官网。

## 交付

说明改动、归档位置、实测结果和待确认项。按本次授权推进远端操作：

- **提交并推送**时核对暂存差异和目标分支。要求等待 CI 时，跟踪实际推送的提交；失败就查日志，修复后按新提交重新验收。
- **部署现有正式版官网**时，只调用官网部署入口。等待部署成功，再访问公开首页、安装教程和下载链接，核对实际指向的版本。
- **发布新版本**时，遵循仓库自己的发布流程；单独的清理、推送或官网部署请求不包含发版授权。
