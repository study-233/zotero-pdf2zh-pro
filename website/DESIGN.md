**参考 Memos 的设计逻辑，不要直接克隆 Memos 品牌**。目标是网页看起来像一个认真设计的独立软件产品：安静、自然、精致，产品本身有说服力。

具体借鉴：
- 编辑式的标题层级与左对齐布局，而不是常见 AI SaaS 的巨大居中宣传标题。
- 明亮、中性且几乎没有装饰的画布；细致但不突兀的灰阶。
- 柔和的蔚蓝色只在操作、链接与重点信息中出现。
- 首页最强的视觉资产是一个具体、真实的产品画面。
- 用不等分栏、开放列表、内容之间的关系组织版块，避免密集的大卡片墙。
- Hero 高度由内容决定，不以 100vh、人为留白或空装饰撑满。

**必须适配 Zotero 产品截图**：Memos 的 Hero 演示偏竖向界面；本项目的双语 PDF 阅读截图更宽，因此允许“文字较紧凑＋全宽大图”，而不是必须机械模仿左文右图。

## 2. 当前网站必须纠正的问题

- 当前页有两层顶部导航，导致主要内容被向下推。
- 中心巨型标题、长副标题与 CTA 占用过多首屏空间。
- 产品截图出现在首屏底部，真实功能难以辨认。
- 模拟 GitHub 仓库的 `study-233 / zotero-pdf2zh-pro`、`Public` 等包裹元素没有实际信息价值。
- 开源、版本、支持范围、产品定位重复出现，构成“徽章＋文案”噪声。
- 大面积黑底、强分隔和外层厚重边框让页面更像开发者模板，而不是 Memos 式阅读工具网站。

**不是换皮肤**：不能只将背景变白、按钮变蓝、字体换一下，就宣称达到目标。需要调整页面骨架与信息位置。

## 3. 视觉与排版约束

| 部位 | 规则 |
|---|---|
| 主背景 | 接近白色，暗色是柔和深灰而不是全黑 |
| 文字 | 深灰、清晰的中性层级，正文以现代系统无衬线为主 |
| 强调 | 少量柔和蔚蓝色；不强制 Primer 原色值 |
| 标题 | 允许适度编辑式衬线气质，但中文字体须检验 Windows/macOS 回退；不强制装载巨型中文字体文件 |
| 布局 | 1440px 宽下主内容容器约 1180–1280px，首页保持适当左右留白 |
| 圆角 | 常见 6–12px，避免每个模块都有厚卡片 |
| 分隔 | 用留白和对齐优先；只有必要时用浅色边框 |
| 动效 | 很轻，交互反馈优先；尊重减少动画偏好 |

**参考色值是提案，不是 Memos 的精确官方 token：**

| Token | 浅色 | 深色 |
|---|---|---|
| `--site-bg` | `#FFFFFF` | `#17191D` |
| `--site-surface` | `#FFFFFF` | `#202329` |
| `--site-muted-bg` | `#F7F8FA` | `#262A31` |
| `--site-text` | `#20242A` | `#F1F3F5` |
| `--site-muted-text` | `#626B77` | `#A6ADB8` |
| `--site-border` | `#E4E7EB` | `#343940` |
| `--site-accent` | `#356F9E` | `#A5C8E8` |

以视觉自然、文本可读和组件统一为优先，不要为了匹配 HEX 扭曲排版。成功状态的绿色可以保留，但普通品牌按钮不必为绿色。

## 4. 首页结构

**一行导航**\
Logo / 使用教程 / 模型评测 / 更新记录 / 搜索 / GitHub / 下载。桌面不允许第二层导航。移动端可折叠。

**Hero：一个信息主张＋一个视觉证明**
- H1：「在 Zotero 中翻译论文」
- 一句介绍：「生成双语 PDF，自动导回原条目；支持查词和选段翻译。」
- 主按钮：「下载与安装」
- 次入口：「使用教程」
- 版本、许可、Zotero 兼容范围小字号展示在合适的地方，不套徽章墙。
- 真正展示整篇论文的双语效果。图片保持自身比例、足够清晰、必要时可放大。
- 1440×900 桌面截图中，应在首屏看到**实质性的**产品画面，不能只有截图标题或边框出现在屏幕最底部。

**接下来的内容**
1. 真实划词精读截图及极简说明，避免重复同一双语图。
2. 批量、补译、术语、文档导出使用一行短链接；模型评测保留在主导航。
3. 下载区只展示本地服务与 XPI，完整首次使用流程进入教程。
4. 保留 Windows/macOS 的差异，macOS 显示真实命令和 Intel 限制。
5. 极简页脚保留开源协议、上游署名、反馈和文档。

不要凭空添加用户评价、合作品牌、统计增长、复杂特效等营销元素。

## 5. 固定禁止事项

- 不要仿 GitHub 仓库 UI；删除 Public/假仓库工具栏/假状态信息。
- 不要双层导航。
- 不要大面积渐变、玻璃拟态、背景光球、发光描边。
- 不要每个能力都套独立有阴影的卡片。
- 不要在不同段落重复“开源、免费、Zotero、翻译、双语”等同义信息。
- 不要用泛 AI 营销词（赋能、重新定义、无缝、革命性、未来、效率飞跃等）。
- 不要伪造 Zotero 截图、伪造正在运行的任务或生成看似真实的软件 UI。
- 不要为了复制 Memos 的 Next.js 组件重写网站技术栈；仍用 Astro + Starlight。
- 不要因审美改版删除 macOS Apple Silicon 限制、API 数据与费用说明、旧路由和重要下载入口。

## 6. Codex 修改流程

1. 先读 `website/DESIGN.md`、`AGENTS.md`、现有源码和网站截图。
2. 查阅 Memos 官网及 `DESIGN_SYSTEM.md`、Hero 组件源码；总结 Memos 的 3–5 个可观察的设计特征。若无法访问外网，只依据已有规范和可读取文件，不虚构。
3. 先识别网站的核心任务和最强视觉证明，再决定 Hero 该采用分栏还是大图；不能先套模板。
4. 对照当前页面截图，先画出新的页面信息层级，再修改代码。
5. 实现后启动预览，用浏览器截取 1440×900、390×844 的浅色/深色页面。
6. 与旧页面、Memos 参考网页对比：产品截图实际可见区域、顶部高度、标题长度、空白、卡片密度、按钮层级。
7. 如果没达到目标，继续一轮视觉迭代，**不能只因代码可构建就结束**。
8. 回归旧链接、XPI/EXE 下载、四步安装、模型评测、多主题与响应式；不改变插件/服务功能。
9. 提供新的截图、修改文件列表、测试结果和仍需人工拍摄的截图清单。

## 7. 最终验收标准

- [ ] 顶部只有一行导航。
- [ ] 1440×900 页面首次打开时可以直观看到真实 Zotero 双语 PDF 内容。
- [ ] 图片没有仿 GitHub 包装，整体以实际产品画面而非装饰为中心。
- [ ] 页面具有 Memos 式安静、自然、编辑式排版；没有默认 AI 营销页的“巨型居中标题＋渐变光球＋卡片墙”。
- [ ] 标题和功能文案经过精简；重要兼容、隐私和费用条件未丢失。
- [ ] 390px 和 320px 宽度没有水平滚动，触屏交互正常。
- [ ] 亮暗主题对比度与文字可读性合格，键盘焦点明显。
- [ ] 文档搜索、旧路由、安装资源、评测图表及下载数据功能未退化。

**一句话：Memos 的排版和产品展示哲学，加上 Zotero 自己的真实界面，而不是一张“模仿 Memos 的模板”。**
